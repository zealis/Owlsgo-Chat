# 更新日志（CHANGELOG）

> 类型：**安全 / 修复 / 新增 / 改进 / 重构 / 移除**。每次发版执行该脚本即可更新。

## v1.1.0（2026-10-02）

私聊从「弹窗发一条」升级为完整会话：可翻历史、可双向续聊、按最后活跃时间排序，与群聊共用同一套消息区 / 输入栏 / 列表交互。

- **新增**：私聊会话（独立于群聊，落在虚拟空间 `room_id=0`），可翻历史、双向续聊
- **新增**：通用聊天列表轮子 `ChatList`（`.ow-cl-*`），群聊与私聊共用一份渲染与点击分发
- **新增**：会话聚合接口 `conversations`，群聊 + 私聊按最后活跃时间倒序统一排序
- **新增**：私聊增量轮询 `dm_poll`（20s 长挂起，与群聊 poll 同构）
- **新增**：头像右键菜单、用户资料卡均可直接进入私聊会话页
- **新增**：会话列表低频轮询 `startConvPoll`（10s），任何会话来了新消息自动置顶，无需手动刷新
- **新增**：前端插件钩子 `OwChat.onViewChange(ctx)`（`ctx.view` 为 `room` / `dm`），供插件按视图自行清理或复原群级装饰
- **改进**：左侧栏标题「群聊」→「聊天」，徽标含义改为会话总数（群聊数 + 私聊会话数，由 `conversations` 接口回传 `total`）
- **安全**：私聊仅双方可见——`visible()` 移除管理员越权例外，超级管理员与后台同样不可查看他人私聊
- **安全**：私聊对象强制 `user:<id>` / `guest:<id>` 数字标识，拒绝自我私聊与非法 / 注入式输入
- **修复**：跨身份私聊（用户↔游客）历史永远查不到——原条件忽略对方 kind，且两分支列顺序相反时 SQLite 在 `EMULATE_PREPARES=false` 下复用错位绑定值，只查得到自己发出的那条
- **修复**：私聊链接自我失效——`setDmUrl` 用 `encodeURIComponent` 把 `:` 编成 `%3A`，而 `dmFromUrl` 按字面冒号匹配，应用自己写出的链接自己都解析不出来
- **修复**：「加载更早消息…」每次切换会话被 `innerHTML` 重建，onclick 绑定丢失 → 改为父容器事件委托
- **修复**：私聊页仍显示「→ 昵称」（该标注仅群聊内私信有意义）与空的「加载更早消息…」
- **修复**：接收方看不到别人发来的私聊——`conversations()` 只匹配发送方列（`user_id`/`guest_id` = 我），「对方发给我」的私聊在接收方列表里完全不出现；现改为收发双向匹配
- **安全**：修复上一条时顺带消除的越权隐患——未使用的身份列存的是 `0` 而非 `NULL`，`to_guest_id = 0` 会匹配到全站所有人的私聊；现对未使用列改用 `> 0` 严格判定，且游客分支仅在确有游客身份时才参与匹配
- **修复**：群公告被带进私聊区——`openDm()` 原不触发房间切换钩子，公告插件的 `current.roomId` 仍指向上一个群，公告条留在私聊页；现由 `onViewChange` 钩子通知插件在私聊视图清掉群级装饰，切回群聊再复原
- **修复**：在其他群聊点刷新 100% 跳到第一个群聊——从私聊切回群聊时 `setRoomUrl` 只删 `room=` 不删 `dm=`，URL 残留 `?dm=…&room=N`，刷新时 `dmFromUrl()` 优先解析而强制跳回私聊；现两参数严格互斥，`popstate` 亦改为优先认 `room`
- **改进**：取消私聊顶部的「私聊」徽标与消息内的「→ 昵称」私信文字标签，私聊页标题只显示对方昵称
- **改进**：群聊 / 私聊长轮询用世代号互斥，避免两个 in-flight 请求互相覆盖 `since` 与消息区
- **改进**：`dm_history` 一并回传对方资料，首次私聊也能显示真实昵称而非占位「私聊」
- **重构**：存量私信（1.0.x 的 `room_id>0`）迁移进 `room_id=0` 虚拟私聊空间，迁移幂等
- **重构**：删除失效的 `renderRooms`，群聊列表刷新统一走 conversations 聚合接口

### v1.1.0 第二批（2026-10-03）：合规查阅、软删除、游客发言间隔

- **新增**：插件 `dm-compliance`（私聊合规查阅）——经 `dm.read` 钩子为**超级管理员**开一个显式合规查阅入口，按用户 ID + 时间范围检索其参与的全部私聊，满足《个人信息保护法》第 35 条、GDPR 合法利益例外等「有合法权限时须可调取」的法规要求
- **安全**：合规查阅**默认关闭 + 强制留痕**——插件未注册 `dm.read` 钩子时物理上无法查阅（停用即失效）；`role` 必须为 `admin`，member 与游客一律拒绝；无论命中与否都写 `security_logs`（合规答复需举证「查过但没有」）；核心与插件各校验一次（纵深防御）；全程只读，不提供任何写路径
- **安全**：核心 `dm-privacy` 硬约束（私聊仅双方可见，管理员亦不例外）**未被放开**——新增的 `Chat::dmComplianceRead()` 是唯一能绕过 `visible()` 的入口，其余路径一律不变
- **重构**：消息删除**全量改为软删除**（含超级管理员）——行保留、`content` 与 `quote` 清空（原文不可恢复），昵称 / 时间 / IP 等元数据留存以备审计；不设「超管绕过保留期」的旁路，任何人都无法提前物理清除
- **新增**：系统设置「已删除消息保留期(天)」，默认 30 天，0 表示永久保留；到期后由 `Chat::purgeDeleted()` 统一物理清除（读消息时顺带触发，小时级节流，失败静默不影响主流程）
- **改进**：`messages` 表新增 `deleted` / `deleted_at` / `deleted_by` 三列（幂等迁移），前台按 `deleted` 标记显示「该消息已删除」虚线占位，与撤回文案区分
- **新增**：系统设置「游客发言间隔(秒)」，默认 30，**取代**原「游客每日发言限额」；复用 `rate_limits` 表（`bucket=guest_gap`）实现，不新增表结构；0 表示不限制，登录用户不受影响
- **移除**：`guest_daily_limit` 默认值下线，`ensureGuest()` 不再写 `daily_count` / `daily_date`（`guests` 表列保留不动，规避 SQLite 删列重建风险）
- **改进**：消息时间不再紧贴头像远端，改为**紧跟昵称**；且仅在鼠标悬停消息气泡**满 2 秒**后才显示，移开立即隐藏并清理计时器（CSS `:hover` 无法表达「持续满 N 秒」）
- **改进**：自己的消息整行镜像（`row-reverse`）时用 `order:-1` 把时间拉回昵称**右侧**，避免时间被甩到昵称左边
- **修复**：游客身份不再出现头像右键菜单的「禁言」项——`BM.canBan()` 改为显式判 `actor.kind === 'user'`，不再依赖「`cfg.me` 为 null 时 `me.id` 抛异常被 `try/catch` 吞掉」这种顺带成立的副作用
- **改进**：私聊消息气泡与群聊**完全一致**——移除 `.ow-msg.private` 的独立紫色配色与 `::after` 追加的「[私信]」标签
- **安全**：`quote` 列存在 `NOT NULL` 历史约束，软删除时写空串而非 `NULL`（否则触发 SQL 完整性错误）
- **修复**：`dmComplianceRead()` 在 `Plugin` 类未加载的精简部署（如 CLI 批处理）下会 fatal error——补 `class_exists('Plugin')` 防御，此时合规能力应「不可用」而非崩溃
