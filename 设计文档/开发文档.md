## 前言
开发一个即时通讯系统，取名叫Owlsgo-Chat，也可以叫OChat。这是一个基于原生 PHP 8.1+ + SQLite、MySQL 和 PostgreSQL+ Workerman WebSocket 构建的现代化实时聊天室，无需框架依赖，开箱即用。采用自研扁平化 UI 设计（类名为ow开头），支持插件机制。适合web在线聊天、低成本部署和 AI 二次开发，完整适配移动端的系统。


## 特点

- 纯原生 PHP，单核心代码文件，无框架和 Composer 依赖，部署与维护简单
- 支持 SQLite、MySQL 和 PostgreSQL，数据库结构和搜索能力保持跨引擎兼容
- 支持用户角色、聊天室权限、站点设置、注册控制、发言限制和附件管理
- 插件机制支持 Hook、路由、后台页面、资源合并、在线安装更新和统一计划任务
- 站点设置、聊天附件和用户按需懒加载，数据库结构简单，负载能力强
- 支持 AJAX 交互和响应式布局，兼顾 PC 与移动端使用体验

## 开发约束

### 图片上传：一律原图直存，不压缩、不转码、不走图床（v1.0.35 起）

⚠️ 硬性规则：头像 / 贴纸 / 图片消息全部走 `Upload::local()` 原样保存，客户端不做 canvas 压缩，
服务端不转发图床。曾经的 `compressImage()`（客户端缩放 + JPEG 0.85 重编码）与 `Upload::imgbed()`
及 `image_mode` 设置项已全部移除，**不要重新引入任何压缩或第三方图床链路**。
体积控制只靠 `upload.max_size`（服务端兜底 10MB）与后台「单文件大小上限」。

### 用户标识：只有用户 ID，没有用户名（v1.0.33 起）

⚠️ 硬性规则：本项目已于 v1.0.33 取消「用户名」（`users.username` 列随迁移物理删除）。
任何时候不得重新引入 `username` 字段，也不得用昵称、邮箱作为用户的身份标识。

1. **代表用户一律用 `user_id`**
   资料卡跳转（`OwChat.userCard(uid)`）、私信目标（`to_user_id`）、前台 `boot.me`、
   后台用户管理、房主归属（`rooms.owner_id`）、插件 getUser 类实现——
   凡是「指向某个用户」的参数、字段、外键、缓存键，必须是数字用户 ID。

2. **昵称 `users.nickname` 只是显示名**
   - 允许重名，**不做唯一性校验**（这是"取消用户名"的实质含义，勿回滚）；
   - 规则：2-20 个字符，字符集 `[\p{L}\p{N}_-]`（中英文 / 数字 / 下划线 / 短横线）；
   - **禁止空格与 `@`**：服务端 @提及 按 `(^|\s)@[^\s@]+` 切词，含空格会导致该用户无法被提及；
   - 规则统一走 `Auth::checkNickname()`，注册、安装、个人设置三处共用，勿各自写正则。

3. **登录标识只有两种：注册邮箱 / 用户 ID**（见 `Auth::login()`），不允许再增加第三种。

4. **后台用户搜索只支持数字用户 ID 精确查询**（见 `Admin::handle()` 的 `admin_users`）。
   昵称 / 邮箱因可重名或不唯一，不可作为检索依据，只能作为结果展示。

5. **新增表若需关联用户，列名用 `user_id`**，并在文档与代码中注明它是身份键。

6. **迁移约定**：老库升级时执行 `UPDATE users SET nickname=username` 后删除该列；
   SQLite 不允许删除带 UNIQUE 约束的列，由 `DB::dropColumn()` 退化为重建表处理，勿改为手动绕过。
## 设计备忘录

> 本节记录跨版本长期有效的架构约定，**新功能一律遵守**；与既有条目冲突时以本节为准。

### 敏感操作安全校验（v1.0.91 起）

⚠️ 硬性规则：凡是「不可逆 / 影响他人 / 影响账号安全」的操作，必须接入敏感操作校验，
不得只靠普通签名提交。

1. **敏感操作范围**（当前已覆盖，新增同类功能必须照做）：
   - 退出登录（`logout`）；
   - 删除内容：撤回 / 删除消息（`recall`、`msg_delete`）、贴纸删除（`sticker_del`）、
     公告删除（`admin_ann_del`）、敏感词删除（`admin_word_del`）、附件删除（插件）；
   - 管理员删 / 恢复数据：群聊删除（`admin_room_del`）、审核撤销（`admin_room_trash_undo`）、
     批量处置（`admin_room_batch`）、插件卸载（`admin_plugin_uninstall`）；
   - 账号与权限类：用户禁用 / 用户组修改（user-manager 插件）、禁言（ban-manager 插件）、
     关闭两步验证 / 重置恢复码（twofa 插件）；
   - 今后任何「清理缓存、批量清理、重置、导出后删除源」类接口，**上线前必须**按下述机制标记。

2. **服务端机制**（index.php API 入口统一拦截）：
   - 核心敏感 action 列表维护在 `$SENSITIVE`；插件路由用
     `Plugin::route($action, $fn, ['sensitive' => true])` 或注册后追加
     `Plugin::sensitive($action)` 声明（清单随插件缓存持久化）；
   - 校验内容：仅接受 **POST** + **一次性操作票据**（`Sec::ticketVerify()`）；
   - 票据由 `?action=ticket` 签发（需签名，写入会话），**校验通过立即作废**，5 分钟有效；
     即使签名被截获也无法重放（票据一次性），跨站请求因拿不到票据而被拒；
   - 校验失败写安全日志（`Sec::log('sensitive_reject', ...)`）。

3. **前端机制**：统一用 `OwApi.secure(action, data, cb)` 调用（自动先取票再提交），
   不要直接 `OwApi.post` 敏感接口；`OwApi.secure` 同时被 OwAdmin / 插件 JS 使用。
   敏感操作在 UI 层保留二次确认弹窗（`confirmModal` / `OwAdmin.confirm`），两层防护缺一不可。

4. **会话锁注意**：ticket 签发与敏感操作必须保持会话可写（index.php `$keepSession`），
   新增敏感 action 时无需改这里（由 `$SENSITIVE` / 插件清单自动覆盖）。

### 插件代码按需加载（v1.0.90 起）

1. `Plugin::init()` 不再在每个请求 require 全部 `main.php`；改为读取
   `data/cache/plugins.json`（元数据 + 注册清单：钩子 / 路由 / 后台页 / 敏感标记 / 资源），
   请求周期内只在实际用到时才加载对应插件代码。

2. **对插件的硬性契约**：`main.php` 顶层只做 `Plugin::*` 注册（on / route / adminPage /
   asset / sensitive），不做输出、不依赖加载顺序、不产生其它副作用——清单缓存与后台探测
   机制都依赖此约定。

3. 新增钩子 / 路由无需手工更新缓存：插件文件 mtime 变化后，首个相关请求会自动重建清单。

4. 资源合并（`?action=assets`）走清单 + 合并缓存；插件新增 JS/CSS 后刷新页面即自动生效。

### 登录会话与 Cookie 安全（v1.0.94 起）

1. **会话指纹绑定**：会话创建时记录 `sec_fp`（User-Agent + IP 前两段/IPv6 前三组的 SHA-256），
   每个请求在 `Sec::fingerprintGuard()`（DB::init 之后、Auth::user 之前）比对，
   不匹配即销毁会话并写安全日志 `session_fingerprint_mismatch`——
   登录 Cookie 被跨站窃取 / 本地读取后，换浏览器或换网络重放无效。
   注意：必须在 `DB::init` 之后调用（守卫拒绝时要写日志），否则 PDO 未初始化直接 fatal。
2. **Cookie 参数基线**：会话与身份 Cookie 一律 `httponly + samesite=Lax`，
   `secure` 由 `Sec::isHttps()` 动态决定（https 部署自动开启；本地 http 不开启）；
   匿名签名密钥 `owl_akey` 有效期 7 天（与会话一致），游客令牌 `owl_guest` 1 年。
3. **会话固定防护**：登录成功时 `session_regenerate_id(true)`（Auth::login 已有，勿删）。
4. 敏感操作另有 v1.0.91 一次性票据（见上节），两层互不替代。

### 访客 IP 获取规范（v1.0.98 起）

⚠️ 硬性规则：全项目获取访客 IP **只能通过 `Sec::ip()`，且其唯一数据源是
`$_SERVER['REMOTE_ADDR']`**（服务器原始地址，取自 TCP 连接对端，客户端无法伪造）。

1. **禁止读取任何可伪造头**：`X-Forwarded-For`、`X-Real-IP`、`CF-Connecting-IP`、
   `Client-IP` 等——攻击者可直接构造这些头冒充任意 IP，污染安全日志、绕过 IP 禁言
   （ban-manager）与登录/发言限频。全项目 12 处 IP 消费点（日志、禁言、限频、指纹等）
   均已收敛到 `Sec::ip()`，不得旁路。
2. **反代部署的正规做法**：如站点置于可信反向代理之后，应在代理层把真实客户端 IP
   写入 `REMOTE_ADDR` 传递（`fastcgi_param REMOTE_ADDR $真实IP变量`），
   PHP 代码永远只读 REMOTE_ADDR，一行都不改。
3. **`ow_site_url()` 例外说明**：该函数读 `X-Forwarded-Host/Proto` 仅用于
   **生成资源链接**（站点地址自动识别，反代场景必需），不参与鉴权与重定向决策；
   管理员在后台手动配置 site_url 后自动识别分支即被完全关闭。

### ⚠️ 禁止浏览器原生弹窗（v1.0.112 起硬性约束，历次违反重点）

前台与插件 **一律使用自研弹窗**，**禁止 `confirm()` / `alert()` / `prompt()`**：
- 确认类 → `OwChat.confirm(text, onOk)`（前台，v1.0.112 新增前台版）/ `OwAdmin.confirm`（后台）；
- 消息提示 → `toast(msg)`；
- 输入类 → `OwChat.openModal(html)` 自建表单弹窗（参照私信弹窗 pm 实现）。

**每次发版前必须执行检查**（出现任何一行即违规）：
```
grep -rn "w\.confirm(\|window\.confirm(\|[^.a-zA-Z]alert(\|w\.prompt(" assets/js/chat.js plugins/*/*.js
```
已知违规历史：v1.0.112 前公告删除用 w.confirm、私信用 w.prompt、twofa 两处降级 alert——全部已修复。
