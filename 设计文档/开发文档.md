## 前言
开发一个即时通讯系统，取名叫Owlsgo-Chat，也可以叫OChat。这是一个基于原生 PHP 8.1+ + SQLite、MySQL 和 PostgreSQL+ Workerman WebSocket 构建的现代化实时聊天室，无需框架依赖，开箱即用。采用自研扁平化 UI 设计（类名为ow开头），支持插件机制。适合web在线聊天、低成本部署和 AI 二次开发，完整适配移动端的系统。


## 特点

- 纯原生 PHP，单核心代码文件，无框架和 Composer 依赖，部署与维护简单
- 支持 SQLite、MySQL 和 PostgreSQL，数据库结构和搜索能力保持跨引擎兼容
- 支持用户角色、聊天室权限、站点设置、注册控制、发言限制和附件管理
- 插件机制支持 Hook、路由、后台页面、资源合并、在线安装更新和统一计划任务
- 站点设置、聊天附件和用户按需懒加载，数据库结构简单，负载能力强
- 支持 AJAX 交互和响应式布局，兼顾 PC 与移动端使用体验

## 开发约束

### 图片上传：一律原图直存，不压缩、不转码、不走图床（v1.0.35 起）

⚠️ 硬性规则：头像 / 贴纸 / 图片消息全部走 `Upload::local()` 原样保存，客户端不做 canvas 压缩，
服务端不转发图床。曾经的 `compressImage()`（客户端缩放 + JPEG 0.85 重编码）与 `Upload::imgbed()`
及 `image_mode` 设置项已全部移除，**不要重新引入任何压缩或第三方图床链路**。
体积控制只靠 `upload.max_size`（服务端兜底 10MB）与后台「单文件大小上限」。

### 用户标识：只有用户 ID，没有用户名（v1.0.33 起）

⚠️ 硬性规则：本项目已于 v1.0.33 取消「用户名」（`users.username` 列随迁移物理删除）。
任何时候不得重新引入 `username` 字段，也不得用昵称、邮箱作为用户的身份标识。

1. **代表用户一律用 `user_id`**
   资料卡跳转（`OwChat.userCard(uid)`）、私信目标（`to_user_id`）、前台 `boot.me`、
   后台用户管理、房主归属（`rooms.owner_id`）、插件 getUser 类实现——
   凡是「指向某个用户」的参数、字段、外键、缓存键，必须是数字用户 ID。

2. **昵称 `users.nickname` 只是显示名**
   - 允许重名，**不做唯一性校验**（这是"取消用户名"的实质含义，勿回滚）；
   - 规则：2-20 个字符，字符集 `[\p{L}\p{N}_-]`（中英文 / 数字 / 下划线 / 短横线）；
   - **禁止空格与 `@`**：服务端 @提及 按 `(^|\s)@[^\s@]+` 切词，含空格会导致该用户无法被提及；
   - 规则统一走 `Auth::checkNickname()`，注册、安装、个人设置三处共用，勿各自写正则。

3. **登录标识只有两种：注册邮箱 / 用户 ID**（见 `Auth::login()`），不允许再增加第三种。

4. **后台用户搜索只支持数字用户 ID 精确查询**（见 `Admin::handle()` 的 `admin_users`）。
   昵称 / 邮箱因可重名或不唯一，不可作为检索依据，只能作为结果展示。

5. **新增表若需关联用户，列名用 `user_id`**，并在文档与代码中注明它是身份键。

6. **迁移约定**：老库升级时执行 `UPDATE users SET nickname=username` 后删除该列；
   SQLite 不允许删除带 UNIQUE 约束的列，由 `DB::dropColumn()` 退化为重建表处理，勿改为手动绕过。
### 私聊会话：虚拟空间 + 仅双方可见 + 轮询互斥（v1.1.0 起）

⚠️ 硬性规则：私聊已从「群内发一条私信」升级为独立会话，任何新代码都不得再把私聊当作群聊消息处理。

1. **私聊落在虚拟空间 `room_id=0`**，不隶属任何群聊。
   `Chat::send()` 据此跳过群校验与群禁言；`Chat::room(0)` 不存在是正常的。
   1.0.x 的存量私信（`room_id>0`）由 `DB::migrate()` 幂等搬入 `room_id=0`，勿重复手写迁移。

2. **对象标识沿用「只有用户 ID」规则**：私聊 peer 统一为 `user:<数字id>` / `guest:<数字id>`，
   解析与校验一律走 `Chat::dmPeerKey()`（拒绝自我私聊、非法格式与注入式输入）。
   昵称仅作展示快照，**不得**用它做身份标识或反查。

3. **私聊仅双方可见，管理员亦不例外**
   `Chat::visible()` 只放行发送方与接收方；超级管理员与后台管理同样不可查看或代读他人私聊。
   新增任何私聊查询（历史 / 轮询 / 导出 / 后台）都必须经 `visible()` 或 `dmPairConds()` 收口。

   ⚠️ **唯一例外**（v1.1.0 起）：法定合规调取走 `Chat::dmComplianceRead()`，
   这是**唯一**允许非当事人读取私聊内容的入口，详见下文「私聊合规查阅」一节。
   除它之外，任何代码都不得绕过 `visible()`。

4. **两条长轮询必须互斥**
   群聊 `poll` 与私聊 `dm_poll` 共用同一消息区与输入栏。切换视图时自增世代号
   （`OwChat.pollGen` / `OwChat.dmGen`）让旧循环自毁，禁止两个 in-flight 请求同时
   刷新 `#owMessages` 或互相覆盖 `since`（会导致消息重复、since 回退、串会话）。

5. **写私聊 SQL 的两个硬性陷阱**（都已实际踩过，务必记住）：
   - 每个分支必须写成「发送方列 = ? AND 接收方列 = ?」，**发送方列在前**。
     写成 `to_user_id=? AND user_id=?`（接收方在前）时，SQLite 在
     `ATTR_EMULATE_PREPARES=false` 下会复用错位的绑定值 → 只查得到自己发出的那条。
   - 跨身份（用户↔游客）时「对方→我」那一支的发送方列必须换成对方的列
     （`guest_id` ↔ `user_id` 互换），否则该支永不成立。
   统一用 `Chat::dmPairConds()` / `dmPairSql()` 拼条件与参数，不要手写。

6. **列表与标题**
   左侧栏为「群聊 + 私聊」聚合列表（`Chat::conversations()`，按最后活跃时间倒序），
   渲染统一走 `ChatList` 轮子（`.ow-cl-*`），**勿再调用已删除的 `renderRooms()`**。
   私聊页标题依赖 `dm_history` 回传的 `peer.name`；会话列表尚未包含该项时也能显示真实昵称。
   侧栏标题为「**聊天**」（不是「群聊」），徽标数字是**会话总数**（群聊数 + 私聊会话数），
   由 `conversations` 路由回传的 `total` 填充，勿再用 `count($rooms)` 之类只算群聊。

7. **地址路由**：`?dm=user:12`，冒号**不得**编码（`encodeURIComponent` 会变成 `%3A`，
   导致应用自己写出的链接自己解析不出来）。`dmFromUrl()` 兼容编码形式。

8. **`dm` 与 `room` 在 URL 上严格互斥**（v1.1.0 起，踩过「刷新跳第一个群聊」的坑）
   - `setRoomUrl()` 必须**同时**清掉 `dm=` 与 `room=` 再写 `room=`；
     只删 `room=` 会残留 `?page=chat&dm=user:20&room=2`，刷新时 `dmFromUrl()` 优先解析
     → 明明在群聊里却被强制拽回私聊（表现为「100% 跳到第一个群聊」）。
   - `onpopstate` 以 URL 实际内容为准，**先认 `room` 再认 `dm`**（历史遗留 / 外部链接
     可能两者并存，此时优先群聊，避免莫名跳进私聊）。

9. **会话列表必须收发双向匹配，且未使用身份列用 `> 0` 判定**（v1.1.0 起）
   `Chat::conversations()` 聚合私聊时，条件要同时覆盖「我发的」与「发给我的」：
   ```php
   $conds = ['(user_id > 0 AND user_id = ?)', '(to_user_id > 0 AND to_user_id = ?)'];
   $args  = [$mineUser ?: 0, $mineUser ?: 0];
   if ($mineGuest > 0) {           // 游客分支只在确有游客身份时才加入
       $conds[] = '(guest_id > 0 AND guest_id = ?)';       $args[] = $mineGuest;
       $conds[] = '(to_guest_id > 0 AND to_guest_id = ?)'; $args[] = $mineGuest;
   }
   ```
   两个要点：
   - **只写发送方列**（「对方发给我」的私聊在接收方列表里完全不出现，用户反馈「接收不到别人的私聊」）。
   - **必须用 `> 0` 而不是 `IS NOT NULL`**：未使用的身份列存的是 `0` 而不是 `NULL`，
     `to_guest_id = 0`（用户身份时 `mineGuest=0`）会匹配到**全站所有人**的私聊，
     任何用户都能看到别人的会话 —— 这是越权泄漏，不是漏数据。

10. **群级装饰只属于群聊视图**（v1.1.0 起）
    群公告条、群设置入口这类东西在 `room_id=0` 的私聊视图里语义上不成立。
    核心**不直接操作插件 DOM**，而是提供 `OwChat.onViewChange(fn)` 钩子，
    `ctx = { view: 'room'|'dm', roomId, peer, ownerId, isAdmin }`，
    在 `openDm()` 与 `switchRoom()` 末尾触发；注册时立即补发当前视图（插件脚本晚于 init 加载）。
    插件自己判断 `ctx.view` 决定清理还是复原。
    ⚠️ `init()` 的私聊分支**不得**触发 `_fireRoomSwitch()`——此时 `this.room=0`，
    插件按 `room_id=0` 取数据是错的，这正是「公告被带进私聊区」的根因。

11. **会话列表需要独立于消息长轮询的轻量轮询**（v1.1.0 起）
    群聊 `poll` 只监听**当前所在群**，私聊 `dm_poll` 只监听**当前所在私聊**——
    停在群聊 2 时收不到群聊 1 的消息，靠它们无法让「有新消息的会话自动前置」。
    `OwChat.startConvPoll()` 单独开一路 10s 低频轮询，只重渲染左侧栏，
    **不碰消息区 / 输入栏 / 当前会话**，因此不会打断正在进行的聊天或输入草稿。
    当前所在会话有消息时由 `poll` / `dmPollLoop` 立即 `loadConversations()` 做秒级补充。

### 消息删除：全量软删除 + 可调保留期（v1.1.0 起）

⚠️ 硬性规则：**任何人**（含超级管理员）删除消息都只做软删除，不做物理 DELETE。

1. **软删除语义**（`Chat::deleteMessage()`）
   - `deleted = 1`、**`content` 与 `quote` 一并清空**（原文不可恢复）
   - `deleted_at` 记删除时刻、`deleted_by` 记操作者昵称（截断 64 字符）
   - 昵称 / 时间 / IP 等元数据**留存**，供审计「谁在何时删了谁的消息」
   - 删除动作写 `Sec::log('msg_delete', …)`

2. **与撤回（recall）严格区分**
   - 撤回：用户对自己消息的 3 分钟内操作，不涉及合规，前台显示「此消息已撤回」
   - 删除：管理动作，进安全日志，前台显示「该消息已删除」
   - 两者在 `Chat::pack()` 里都返回空 `content`，但 `recalled` / `deleted` 标记不同，
     前端据此选择文案与样式（`.ow-msg.recalled` / `.ow-msg.deleted`，同为虚线弱化）

3. **`quote` 列是 `NOT NULL`（历史建表约束）**
   清空时必须写**空串**而不是 `NULL`，否则 `SQLSTATE[23000] … messages.quote` 直接崩。

4. **物理清理由保留期统一执行**
   - 系统设置 `msg_deleted_retain_days`（天，默认 30，**0 = 永久保留、永不物理删除**）
   - `Chat::purgeDeleted()` 在 `Chat::history()` 里顺带触发，**小时级节流**（static `$lastRun`）
   - 清理失败**静默**（`catch (Throwable)`），绝不能影响正常读消息
   - ⚠️ **不设「超管绕过保留期」的旁路**。这是刻意的：任何人都无法提前物理清除，
     否则合规审计链条会在超管一次误操作后断裂。

5. **删除权限**：超管 + 本人 + 房主；钩子 `msg.before_delete` 可放行或拦截
   （`$allow` 置 false 即拒绝，`$reason` 为展示给用户的理由）。

### 私聊合规查阅：默认关闭 + 显式例外 + 强制留痕（v1.1.0 起）

⚠️ 硬性规则：合规调取私聊**只能**经 `Chat::dmComplianceRead()`，不得为此放开 `visible()`。

背景：上文第 3 条「私聊仅双方可见，管理员亦不例外」与部分司法辖区的法定义务冲突——
《个人信息保护法》第 35 条（国家机关依法查询须严格授权审批）、GDPR 合法利益例外，
都要求「有合法权限时能调取」，且「调取行为本身需可审计」。两者的正确共存方式是：

1. **默认关闭**：核心在 `dmComplianceRead()` 里 `fire('dm.read', [&$allow, …])`，
   `$allow` 初始为 `false`。**只有插件注册 `dm.read` 钩子并显式置 true 才放行**。
   → 插件未安装 / 未启用时，路由根本不存在，**物理上无法查阅**。
   ⚠️ 必须写 `class_exists('Plugin')` 防御：某些精简部署（仅 CLI 批处理）不加载 `Plugin` 类，
   此时合规能力应「不可用」而不是 fatal error。

2. **仅超级管理员**：`$actor['role']` 必须为 `admin`，`member` 与游客一律拒绝。

3. **强制留痕**：**无论是否查到内容**都写 `Sec::log('dm_compliance_read', …)`，
   含查询条件（`target_id` / `from` / `to`）与命中条数。
   合规场景下「没查到」本身也是需要举证的答复。

4. **只读**：本方法不提供任何写路径，插件也拿不到 DB 句柄以外的东西。

5. **纵深防御**：核心校验 `role==='admin'`，插件路由
   `plugin_dm_compliance_read` 额外校验 `kind==='user'` 并 `Plugin::sensitive()`
   接入一次性票据（CSRF / 防重放）。

6. **日期参数必须校验格式**：`/^\d{4}-\d{2}-\d{2}$/`，否则直接拒绝（防注入 + 防误查）。
   `limit` 收敛到 `max(1, min(1000, …))`。

### 游客发言限制：间隔秒数，不是每日条数（v1.1.0 起）

⚠️ 硬性规则：`guest_daily_limit` 已下线，禁止重新引入。

1. **间隔语义**：`guest_msg_interval`（秒，默认 30，**0 = 不限制**）——
   两条游客消息之间的最小间隔。天级粒度过粗，30 秒既能防洪又不卡死正常聊天。
2. **不新增表结构**：复用 `Sec::rateLimit()` + `rate_limits` 表，`bucket = 'guest_gap'`，
   `ident = 'g' . $actor['id']`，窗口 = 间隔秒数，上限 1 条。
3. **只有游客受限**：判定在 `if ($actor['kind'] === 'guest')` 分支内，登录用户完全不受影响。
4. **返回剩余秒数**：拒绝时把间隔秒数写进提示（「游客发言间隔为 30 秒，请稍后再试」），
   便于前端直接展示，不必二次查询。
5. **`guests` 表的 `daily_count` / `daily_date` 列保留不动**，只是不再写入——
   SQLite 删列需重建表（见「用户标识」节的 `rebuildTableWithout()`），收益不抵风险。

### 消息时间交互：悬停满 2 秒（v1.1.0 起）

⚠️ 硬性规则：消息时间**只在悬停气泡满 2 秒后显示**，位置**紧跟昵称右侧**。

1. **为什么不用 CSS `:hover`**
   CSS 无法表达「持续满 N 秒」。一 hover 就出现会与快速扫读打架，也让昵称行一直跳。

2. **事件委托而非逐条绑定**
   绑定在 `#owMessages` 容器的 `onmouseover` / `onmouseout` 上。
   消息频繁重渲染（`innerHTML` 重建），逐条绑定会随重建丢失（同「加载更早消息…」踩过的坑）。

3. **计时器状态集中在 `OwChat`**
   `_timeMsg`（当前计时中的消息节点）+ `_timeTimer`。
   `hideMsgTime()` 统一清理；**`openDm()` 与 `switchRoom()` 重渲染消息区之前必须先调**
   —— 否则「鼠标已移开但定时器还在跑」会导致时间凭空出现，且引用的节点已不存在。

4. **自己消息的时间在昵称左边，不要用 `order` 拉回来**（v1.1.1 修正）
   自己的消息整行 `flex-direction: row-reverse`（头像在右），meta 行同理。
   DOM 顺序是 `[角色标签, 昵称, 时间]`，被 `row-reverse` 反向渲染成
   「时间 ← 昵称 ← 标签」——即右侧消息的时间落在昵称**左边**，这是它的原有观感。
   ⚠️ v1.0.x 曾用 `.ow-msg.mine .ow-msg-meta .ow-msg-time { order: -1 }` 把时间拉到昵称右边，
   那是对需求的误解（用户只要求改**左侧他人消息**的时间）。该覆盖已删除，别再加回来。

5. **`onmouseout` 要排除移到子元素的情况**：用 `relatedTarget` 判断
   `node.contains(to)`，否则鼠标在气泡内部移动会被误判为「离开」而闪掉。

### 私聊视觉与群聊统一（v1.1.0 起）

⚠️ 硬性规则：`.ow-msg.private` **不得**有任何配色覆盖。

1. 私聊气泡完全由 `.mine` / 非 `.mine` 两个维度决定，与群聊逐字节一致。
   此前私聊用独立紫色气泡 + `::after` 追加「[私信]」，在私聊会话页里纯属噪音
   （页面本身就是私聊，「这是私信」是废话）。
2. 昵称后的「→ 昵称」文字标签一并移除；群聊内 @提及 已足够定位发给人。
3. 回归验证必须**同位置口径**双向比对（私聊 mine vs 群聊 mine、私聊 other vs 群聊 other）。
   跨维度比对必然假失败——气泡配色本就随身份变化。

### 游客不得看到管理类菜单项（v1.1.0 起）

⚠️ 硬性规则：管理类菜单项（禁言等）对游客**必须**完全不可见，且服务端不可达。

1. **显式判身份，不靠副作用**
   `ban-manager` 的 `BM.canBan()` 开头：`if (!actor || actor.kind !== 'user' || !me) return false;`
   ⚠️ 原来靠「游客时 `cfg.me` 为 `null`，`me.id` 抛异常被外层 `try/catch` 吞掉」
   而侥幸正确——行为对但机制脆，插件重构后极易失效。

2. **前端管可见性，服务端管可达性，两层都要有**
   服务端 `ban-manager/main.php`：`if (($actor['kind'] ?? '') !== 'user') Api::json(…, 403);`
   只做前端隐藏等于没做——任何人改个前端就能调接口。

### 群聊信息：单一右侧边栏（v1.1.1 起）

⚠️ 硬性规则：群聊的「设置」与「成员」**共用一个右侧边栏**，入口只有顶栏**竖三点**一个。

1. **DOM 结构**：`#owOnline` 分为两区块——
   - `#owRoomPanel`（上）：群聊设置区
   - `#owOnlineList`（下）：成员列表

   顶栏入口 `id="owTogglePanel"`（图标 `ow_icon('more-v')`）。
   ⚠️ 已删除：列表行内的 `.ow-cl-more` 三点按钮、`#owToggleOnline` 在线成员人形图标、
   `OwChat.openRoomEdit()` 弹窗（改侧栏后无调用者）。
   若日后要恢复弹窗式群设置，**不要**复活这两个入口，否则又回到「两个入口语义割裂」。

2. **设置区按 `room.can_edit` 分双形态**
   - 群主 / 超管：可编辑表单（头像、群名称、群简介、`#owREExtras` 插件入口、保存按钮）
   - 其他身份（含游客）：只读版（简介 + 群主 + 「仅群主与超级管理员可修改」提示）

   `#owREExtras` 在**两种形态下都存在**，插件按 `ctx.isOwner || ctx.isAdmin` 自行决定是否填充。

3. **五处必须刷新设置区**：`init` / `switchRoom` / `openDm` / 打开侧栏 / `reloadRooms`。
   私聊（`room_id = 0`）时显示占位提示，不渲染表单。
   `_roomAvatar`（待保存头像）按 `_roomAvatarRoom` 判断是否重置——否则切群会把上一个群的头像带过来。

4. **`onRoomEdit` 钩子契约**：`fn({ roomId, ownerId, isAdmin, isOwner })`，往 `#owREExtras` 追加。
   触发时机从「打开群聊设置弹窗」改为「设置区渲染」。⚠️ 旧注释里漏写了 `isOwner`（实参一直有），已补。

### 权限可见性一律由服务端下发，前端不自行判身份（v1.1.1 起）

⚠️ 硬性规则：凡是「谁能看见什么」的判定，**必须**由服务端算出布尔随响应下发，
前端只按标志渲染，不在前端重算身份。

1. **在线状态**：`Chat::canSeeOnlineStatus($actor, $roomId)` → `poll` 下发 `online_status`，
   前端 `renderOnline(list, canStatus)` 只按它决定画不画绿点。
   成员**名字对所有人可见**（含游客），只有在线点受限。

2. **群管理入口**：`Chat::rooms()` 的 `can_edit` 必须与插件服务端 `$oaCanManage` **同口径**
   （`role === 'admin'` 直接放行，否则 `owner_id` 命中本人）。
   ⚠️ 踩过的坑：原注释写「超管走后台审核，不在此列」，`can_edit` 只判群主；
   而 announcements 服务端允许超管 → **非群主的超管**拿不到群公告入口，
   表现为「服务端允许删除但前台没有删除按钮」，用户反馈「一些群聊公告在前台删除不了」。

3. **通用教训**：任何有服务端校验的插件能力，前端可见性判定必须与之逐条对齐。
   两处各写一套，迟早漂移——而且漂移方向一定是「服务端允许、前台没入口」，
   因为前端判定写得比服务端更保守时不会有任何报错。

## 设计备忘录

> 本节记录跨版本长期有效的架构约定，**新功能一律遵守**；与既有条目冲突时以本节为准。

### 敏感操作安全校验（v1.0.91 起）

⚠️ 硬性规则：凡是「不可逆 / 影响他人 / 影响账号安全」的操作，必须接入敏感操作校验，
不得只靠普通签名提交。

1. **敏感操作范围**（当前已覆盖，新增同类功能必须照做）：
   - 退出登录（`logout`）；
   - 删除内容：撤回 / 删除消息（`recall`、`msg_delete`）、贴纸删除（`sticker_del`）、
     公告删除（`admin_ann_del`）、敏感词删除（`admin_word_del`）、附件删除（插件）；
   - 管理员删 / 恢复数据：群聊删除（`admin_room_del`）、审核撤销（`admin_room_trash_undo`）、
     批量处置（`admin_room_batch`）、插件卸载（`admin_plugin_uninstall`）；
   - 账号与权限类：用户禁用 / 用户组修改（user-manager 插件）、禁言（ban-manager 插件）、
     关闭两步验证 / 重置恢复码（twofa 插件）；
   - 今后任何「清理缓存、批量清理、重置、导出后删除源」类接口，**上线前必须**按下述机制标记。

2. **服务端机制**（index.php API 入口统一拦截）：
   - 核心敏感 action 列表维护在 `$SENSITIVE`；插件路由用
     `Plugin::route($action, $fn, ['sensitive' => true])` 或注册后追加
     `Plugin::sensitive($action)` 声明（清单随插件缓存持久化）；
   - 校验内容：仅接受 **POST** + **一次性操作票据**（`Sec::ticketVerify()`）；
   - 票据由 `?action=ticket` 签发（需签名，写入会话），**校验通过立即作废**，5 分钟有效；
     即使签名被截获也无法重放（票据一次性），跨站请求因拿不到票据而被拒；
   - 校验失败写安全日志（`Sec::log('sensitive_reject', ...)`）。

3. **前端机制**：统一用 `OwApi.secure(action, data, cb)` 调用（自动先取票再提交），
   不要直接 `OwApi.post` 敏感接口；`OwApi.secure` 同时被 OwAdmin / 插件 JS 使用。
   敏感操作在 UI 层保留二次确认弹窗（`confirmModal` / `OwAdmin.confirm`），两层防护缺一不可。

4. **会话锁注意**：ticket 签发与敏感操作必须保持会话可写（index.php `$keepSession`），
   新增敏感 action 时无需改这里（由 `$SENSITIVE` / 插件清单自动覆盖）。

### 插件代码按需加载（v1.0.90 起）

1. `Plugin::init()` 不再在每个请求 require 全部 `main.php`；改为读取
   `data/cache/plugins.json`（元数据 + 注册清单：钩子 / 路由 / 后台页 / 敏感标记 / 资源），
   请求周期内只在实际用到时才加载对应插件代码。

2. **对插件的硬性契约**：`main.php` 顶层只做 `Plugin::*` 注册（on / route / adminPage /
   asset / sensitive），不做输出、不依赖加载顺序、不产生其它副作用——清单缓存与后台探测
   机制都依赖此约定。

3. 新增钩子 / 路由无需手工更新缓存：插件文件 mtime 变化后，首个相关请求会自动重建清单。

4. 资源合并（`?action=assets`）走清单 + 合并缓存；插件新增 JS/CSS 后刷新页面即自动生效。

### 登录会话与 Cookie 安全（v1.0.94 起）

1. **会话指纹绑定**：会话创建时记录 `sec_fp`（User-Agent + IP 前两段/IPv6 前三组的 SHA-256），
   每个请求在 `Sec::fingerprintGuard()`（DB::init 之后、Auth::user 之前）比对，
   不匹配即销毁会话并写安全日志 `session_fingerprint_mismatch`——
   登录 Cookie 被跨站窃取 / 本地读取后，换浏览器或换网络重放无效。
   注意：必须在 `DB::init` 之后调用（守卫拒绝时要写日志），否则 PDO 未初始化直接 fatal。
2. **Cookie 参数基线**：会话与身份 Cookie 一律 `httponly + samesite=Lax`，
   `secure` 由 `Sec::isHttps()` 动态决定（https 部署自动开启；本地 http 不开启）；
   匿名签名密钥 `owl_akey` 有效期 7 天（与会话一致），游客令牌 `owl_guest` 1 年。
3. **会话固定防护**：登录成功时 `session_regenerate_id(true)`（Auth::login 已有，勿删）。
4. 敏感操作另有 v1.0.91 一次性票据（见上节），两层互不替代。

### 访客 IP 获取规范（v1.0.98 起）

⚠️ 硬性规则：全项目获取访客 IP **只能通过 `Sec::ip()`，且其唯一数据源是
`$_SERVER['REMOTE_ADDR']`**（服务器原始地址，取自 TCP 连接对端，客户端无法伪造）。

1. **禁止读取任何可伪造头**：`X-Forwarded-For`、`X-Real-IP`、`CF-Connecting-IP`、
   `Client-IP` 等——攻击者可直接构造这些头冒充任意 IP，污染安全日志、绕过 IP 禁言
   （ban-manager）与登录/发言限频。全项目 12 处 IP 消费点（日志、禁言、限频、指纹等）
   均已收敛到 `Sec::ip()`，不得旁路。
2. **反代部署的正规做法**：如站点置于可信反向代理之后，应在代理层把真实客户端 IP
   写入 `REMOTE_ADDR` 传递（`fastcgi_param REMOTE_ADDR $真实IP变量`），
   PHP 代码永远只读 REMOTE_ADDR，一行都不改。
3. **`ow_site_url()` 例外说明**：该函数读 `X-Forwarded-Host/Proto` 仅用于
   **生成资源链接**（站点地址自动识别，反代场景必需），不参与鉴权与重定向决策；
   管理员在后台手动配置 site_url 后自动识别分支即被完全关闭。

### ⚠️ 禁止浏览器原生弹窗（v1.0.112 起硬性约束，历次违反重点）

前台与插件 **一律使用自研弹窗**，**禁止 `confirm()` / `alert()` / `prompt()`**：
- 确认类 → `OwChat.confirm(text, onOk)`（前台，v1.0.112 新增前台版）/ `OwAdmin.confirm`（后台）；
- 消息提示 → `toast(msg)`；
- 输入类 → `OwChat.openModal(html)` 自建表单弹窗（参照私信弹窗 pm 实现）。

**每次发版前必须执行检查**（出现任何一行即违规）：
```
grep -rn "w\.confirm(\|window\.confirm(\|[^.a-zA-Z]alert(\|w\.prompt(" assets/js/chat.js plugins/*/*.js
```
已知违规历史：v1.0.112 前公告删除用 w.confirm、私信用 w.prompt、twofa 两处降级 alert——全部已修复。

### 本地回归的测试口径陷阱（v1.1.0 踩过，务必按此写脚本）

浏览器端到端回归（Playwright + 系统 Chrome `channel:'chrome'`）极易得到**假阴性**，
以下两点是本项目的硬性口径：

1. **注入会话必须走 `Sec::sessionStart($CFG)`**
   项目会话名是 `OWLSESSID`，且装了自定义 `SessionHandlerInterface`（会话审计 + 7 天存活，
   见 `core/security.php`）。临时注入脚本若图省事直接写：
   ```php
   if (session_status() === PHP_SESSION_NONE) @session_start();   // ❌ 错
   $_SESSION['uid'] = 20;
   ```
   只会写出 `PHPSESSID`，`index.php` 根本读不到 → 页面**退化成游客身份**
   （`OwChat.init({actor:{kind:'guest', id:297,...}})`），
   表现为「接收方看不到私聊」「游客能发言」等一堆并不存在的 bug。
   正确写法：
   ```php
   define('OWLSGO_VERSION', '1.1.0');
   $CFG = require __DIR__.'/core/config.php';
   require_once __DIR__.'/core/db.php';
   require_once __DIR__.'/core/security.php';
   DB::init($CFG);
   Sec::sessionStart($CFG);          // ✅ 关键
   $_SESSION['uid'] = (int)$_GET['uid'];
   ```
   验证身份是否真的生效：`curl -sk -c jar "…/_smoke_session.php?uid=20" -o /dev/null`，
   再 `curl -sk -b jar "…/?page=chat"` 检查 `OwChat.init({…,"actor":{"kind":"user","id":20}`。

2. **驱动发消息必须走真实输入框路径**
   `OwChat.send({ type: 'text', content: 'x' })` 会**绕过私聊分支**——因为前端判定是
   `if (this.dm && !opt.type)`，显式传了 `type` 就不成立，payload 仍按群聊发
   （`room_id=0` + `type=text`），服务端返回「群聊不存在」。
   真实用户操作不会这样调。正确写法：
   ```js
   document.getElementById('owInput').value = '内容';
   OwChat.send();                    // ✅ 等价于点发送按钮 / 按回车
   ```
   同理，**切换会话要模拟点击侧栏 `<li>`**（会走 `room_join` 鉴权与密码房流程），
   直接调 `OwChat.switchRoom()` 会跳过 `room_join`，出现列表项缺失等假象。

3. **`position:fixed` 元素不能用 `offsetParent` 判可见性**（v1.1.0 踩过）
   `offsetParent` 对 `position:fixed` 元素**恒为 `null`**。右键菜单 `#owCtxMenu`
   正是 `position:fixed`，用它判断会得到「菜单没弹出」的假阴性。
   正确口径：`getComputedStyle(el).display !== 'none' && el.getBoundingClientRect().width > 0`。

4. **消息 DOM 用 `id="owMsg<数字>"`，没有 `data-mid`**
   `document.querySelector('.ow-msg').getAttribute('data-mid')` 返回 `null`，
   `+null` 得 `0` → 后续删除接口拿着 `id=0` 去调，**删掉了别人的消息还断言成功**。
   正确写法：`/^owMsg(\d+)$/.exec(el.id)`。

5. **敏感路由票据一次性，脚本里不能「直调 + 点按钮」混用**
   `OwApi.secure()` 先取 `ticket` 再带票据提交，服务端 `ticketVerify()` 用后即焚。
   若测试先直调接口再点 UI 按钮，两者会互相抢票据 → 后者报
   「安全校验失败，请刷新页面后重试」，是**脚本编排问题而非产品缺陷**。
   `security_logs` 里的 `sensitive_reject` 记录是这类假失败的铁证。

6. **气泡配色比对必须「同位置口径」**
   气泡颜色由 `.mine` / 非 `.mine` 决定，跨维度比必然失败
   （拿私聊的「自己消息」比群聊的「他人消息」→ 一个 `#e6f7ff` 一个 `#f5f7fa」）。
   正确口径：私聊 mine vs 群聊 mine、私聊 other vs 群聊 other，双向都比。

7. **测「默认隐藏」的元素要临时加类再量几何**
   `display:none` 元素 `getBoundingClientRect()` 全为 0，量出的间距无意义。
   正确口径：先 `el.className += ' ow-time-show'` 量完再摘掉。

8. **数据库文件名是 `owlsgo.db` 不是 `owlsgo.sqlite`**
   连错库时 PDO 会静默建一个**空库**——不报错、无输出，只有「查不到任何行」。
   核查数据前先 `ls data/` 确认真实文件名。

9. **站点是 HTTPS，用 `curl -k` / `ignoreHTTPSErrors: true`**
   HTTP 端口（8099）上没有 server 块，会返回 **502 `upstream connect failed`**，
   看起来像 PHP 挂了，实际是协议用错。Nginx 报错日志里的真实请求 `host: localhost` 可佐证。

10. **`?action=assets&type=js` 只合并插件资源，不含核心 `chat.js`**（v1.1.1 踩过）
    `Plugin::renderAssets()` 只遍历插件清单，核心脚本是独立
    `<script src="assets/js/chat.js?v=版本">` 引入的。
    拿合并输出 `grep openDmWith` 得到 0，会误判成「线上跑的是旧版 JS」。
    正确口径：`curl -sk "https://localhost/assets/js/chat.js"` 直接拉静态文件，
    再 `md5sum` 与源文件对照。

11. **`poll` 的返回是扁平合并，不在 `r.data` 里**（v1.1.1 踩过）
    `Api::json(['ok' => true] + Chat::poll(...))` → `online` / `online_status` / `since`
    都在**顶层**。写成 `r.data.online_status` 恒为 `undefined`，
    会把「权限判定写错了」误报成「功能没实现」。

12. **后台是纯前端切页，插件页内容不进首屏**（v1.1.1 踩过）
    `?page=admin` 只渲染菜单骨架，插件页由 `data-apage="plugin:<slug>"` 点击后异步拉取。
    直接 `goto('?page=admin&p=xxx')` 找不到任何表单。
    正确口径：`page.click('#owAdminMenu li[data-apage="plugin:xxx"]')` 再等 1.5s。

13. **切群后不要立刻断言长轮询带回来的数据**（v1.1.1 踩过）
    长轮询最长挂起 20s，`switchRoom()` 后立刻读成员列表会读到**上一轮**的结果
    （或空列表），是假阴性。正确口径：切群后等 ≥2.5s，或直调 `poll`（`timeout: 5`）验证字段。
    ⚠️ 注意这不只是测试问题——真实缺陷也长这样：群聊↔群聊切换时若不作废在途轮询世代，
    旧循环醒来会用**上一个群**的 online 列表刷侧栏，表现为「切了群但成员列表延迟二十秒」。
    `switchRoom()` 现已统一自增 `pollGen` 作废在途请求（v1.1.1 修）。

其他既有纪律：临时文件用完必删（尤其 `_smoke_session.php` 在 WWW 目录、
Playwright 脚本在 node workspace 目录）；opcache `revalidate_freq=60`，
改完 PHP 至少等一次重校验窗口再复查，勿凭一次 curl 就下结论。
